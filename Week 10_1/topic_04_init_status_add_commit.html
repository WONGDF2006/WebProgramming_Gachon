Core commands

# Go to your project folder first
$ cd ~/Desktop/my-project

# Create a repository (makes a hidden .git/ folder)
$ git init -b main

# What does Git see? Always safe to run.
$ git status

# Stage one file, or everything that changed
$ git add index.html
$ git add .

# Save a snapshot with a message
$ git commit -m "Add navigation menu to index.html"

Reading git status

Write useful commit messages: what changed and why. Bad: update. Good: Fix navbar link — it pointed to /about instead of about.html.

Why -b main? Some Git installs still name the first branch master (check with git config --get init.defaultBranch). -b main makes sure it's main, which GitHub expects.

Key points

  • git init creates a repository in the current folder.
  • git status shows what changed. Run it often.
  • git add stages changes; git add . stages all of them.
  • git commit -m "…" saves a permanent snapshot of what's staged.
