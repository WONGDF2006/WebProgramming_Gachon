What works and what doesn't

TechnologyWorks?Why
HTML, CSS✓ YesStatic files, sent as-is
Client-side JavaScript✓ YesRuns in the visitor's browser
fetch() to external APIs✓ YesThe browser calls the API, not the server
Images, fonts, video, PDFs✓ YesStatic files
PHP✗ NoNeeds a PHP interpreter on the server
Node.js / Express✗ NoNeeds a Node runtime: use Render or Railway
Python / Django / Flask✗ NoNeeds a Python runtime
MySQL / MongoDB✗ NoDatabases need a running server
Server-side login / sessions✗ NoUse a service like Firebase Auth instead

Proof from this course: the Week 7 Book Search App calls the Open Library API with fetch(). It works on this GitHub Pages site because the browser does the fetching.

Key points

  • Runs in the browser → works. Needs a server process → doesn't.
  • fetch() to public APIs works fine.
  • For server logic, use serverless functions or a separate backend.
