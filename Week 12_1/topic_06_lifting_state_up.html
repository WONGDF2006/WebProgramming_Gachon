Lifting state up

When two components need the same data, move the state to their nearest common parent. The parent passes the value down as props and passes a callback down so children can ask for changes.

        SearchPage            state: query, results
        ↑ onSearch    ↓ props
   SearchBar        ResultList
 (triggers updates)  (reads via props)

Data flows down. Events flow up. This is React's one-way data model: there is one owner of each piece of state (a single source of truth).

// The parent owns the state
function SearchPage() {
  const [query,   setQuery]   = useState('');
  const [results, setResults] = useState([]);

  const handleSearch = async (q) => {
    setQuery(q);
    const data = await fetchResults(q);
    setResults(data);
  };

  return (
    <>
      <SearchBar onSearch={handleSearch} />            {/* child 1: triggers updates */}
      <ResultList query={query} results={results} />   {/* child 2: reads via props */}
    </>
  );
}

function SearchBar({ onSearch }) {
  const [input, setInput] = useState('');
  return (
    <input value={input} onChange={e => {
      setInput(e.target.value);
      onSearch(e.target.value);
    }} />
  );
}

What not to do

  • Keep a copy of the value in each sibling and try to keep them in sync by hand.
  • Store it in a global variable: React won't re-render when it changes.
  • Change a prop inside the child: props are read-only.

Live: Demo 06 · SearchPage. In my shopping cart, ShoppingCart owns the cart and both ProductList and Cart get it through props.

Key points

  • Shared state lives in the nearest common parent.
  • Pass the value down as props and the updater down as a callback prop.
  • One owner per piece of state.
