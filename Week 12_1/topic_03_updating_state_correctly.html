The functional update form

function Counter() {
  const [count, setCount] = useState(0);

  // Safe: the functional form always gets the latest value
  const increment = () => setCount(prev => prev + 1);
  const decrement = () => setCount(prev => prev - 1);
  const reset     = () => setCount(0);

  // Can be stale when updates pile up:
  // const badIncrement = () => setCount(count + 1);

  return (
    <div>
      <button onClick={decrement}>-</button>
      <span> {count} </span>
      <button onClick={increment}>+</button>
      <button onClick={reset}>Reset</button>
    </div>
  );
}

Why: batching and snapshots

Inside one render, count is a fixed snapshot. React also batches several setState calls made in the same event handler and applies them together after the handler finishes.

// count is 0 in this render
setCount(count + 1);   // queue "set to 1"
setCount(count + 1);   // queue "set to 1" again
setCount(count + 1);   // and again → result: 1

setCount(prev => prev + 1);   // 0 → 1
setCount(prev => prev + 1);   // 1 → 2
setCount(prev => prev + 1);   // 2 → 3 → result: 3

Both buttons are side by side in Demo 02 · CounterState.

Key points

  • Never change state in place; always call the setter.
  • Use setX(prev => …) when the new value depends on the old one.
  • Setter calls in one event handler are batched into one re-render.
