The <button> vs <div> problem

✗ div as a button

<div class="btn" onclick="submitForm()">
  Submit
</div>

<!-- Not reachable with Tab
     Screen reader says only "Submit"
     Enter / Space do nothing
     No disabled state -->

✓ real <button>

<button type="button" onclick="submitForm()">
  Submit
</button>

<!-- Tab stops here
     Screen reader: "Submit, button"
     Enter and Space both work
     disabled attribute works -->

What <button> gives you for free

  • Keyboard focus — no tabindex needed.
  • Enter & Space activation — no keydown handler needed.
  • Built-in role — announced as "button".
  • disabled — removed from Tab order and announced as unavailable.
  • Focus ring — customise it, never remove it.

If you really must use a div: add role="button", tabindex="0", and a keydown handler for Enter and Space. But almost always, you can just use <button>.

Key points

  • <button> for actions, <a href> for navigation.
  • Add type="button" inside forms so the button doesn't submit by accident.
